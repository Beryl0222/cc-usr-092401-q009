# 学校体育实课运行 — 领域设计

面向"每天一节体育课"政策落地的区级核对系统。目标不是考核排名，而是回答一个问题：
**每个班真正上了什么、缺了什么、怎么补**，同时把未成年人数据暴露面压到最小。

本文件与 `pe_domain/` 代码一一对应；每条规则都有可运行的测试用例（`test_pe_domain.py`）。

## 1. 设计原则

1. **方案带版本、授课靠事件、判定靠重放**。批准的学期方案不可改，只能发新版本；
   实课只追加事件；"完成/缺口/异常"全部是事件重放的派生结果，可随时重新计算。
2. **三方最小化交叉确认**。一节课由教师记录、场地观测、抽样学生确认三方共同成立；
   不采影像、不采体测分数、不采集全体学生。
3. **先复核、后结论**。异常只触发教研复核，系统不自动处罚、不公开通报。
4. **评价看过程覆盖，不看单一体测分**。按"教会、勤练、常赛"的可解释规则核对。
5. **分级可见**。公众只看学校聚合；家长只看自己孩子的适配记录；账本中的学生身份是假名。

## 2. 角色与信息流

```
学校管理员 ──提交带版本学期方案──▶ PlanRegistry ──批准版本──▶ 生效课表
体育教师   ──教师授课记录(内容/时长/形态/依据)──┐
场地端     ──场地观测(场地/人数)──────────────┼──▶ 只追加事件账本
抽样学生   ──最小样本到场确认(在线/离线补签)──┘            │
天气/调课/占课/补课 ──依据化事件────────────────────────┤
                                                         ▼
                              重放 rebuild_class → 覆盖规则 → 异常识别
                                                         │
                              复核未结案：仅教研员可见 ◀── ReviewBoard
                                                         │
              公众聚合(k-匿名) / 家长本人子女视图 / 教研证据视图
```

## 3. 学期方案与版本（models.py / plans.py）

方案把 **体育课、大课间、课后服务、班级赛事** 四类活动（`ActivityKind`）逐一对应到
场地、教师、技能目标与安全容量。室外体育课/赛事必须同时声明 **降雨与高温替代**，
替代场地限室内且容量足够；调课、伤病适配都必须挂依据编号（预案条款 / 医嘱 / 申请单号）。

提交前 `validate_plan` 执行可解释的结构校验，问题以 `PlanIssue(code, slot_id, message)` 返回：

| 规则 | code |
|---|---|
| 每周体育课不少于 5 天（每天一节） | `daily_pe_shortfall` |
| 同班同天重复排体育课 | `double_pe_same_day` |
| 同场地/同教师时间冲突（展开奇偶周） | `venue_conflict` / `teacher_conflict` |
| 班级人数超过场地安全容量 | `capacity_exceeded` |
| 教师不具备该技能资质 | `qualification_mismatch` |
| 引用了未定义的技能目标 | `skill_missing` |
| 室外课缺 rain/heat 替代或替代场地不合规 | `weather_alt_missing` 等 |

校验不过只能改后重提，**不产生任何处罚记录**。`PlanRegistry` 对提交分配递增版本号，
批准后冻结；新版本批准时旧版本变 `superseded` 但永久保留——这是识别"阴阳课表"的对照基线：
实际事件永远与**当时生效的批准版本**核对。

## 4. 三方最小化交叉确认（events.py）

一场课（`Occasion = slot + 教学周`）须同时具备：

1. **教师记录** `TeacherReport`：实际技能、实际时长、授课形态、实际场地，替代/调课依据；
2. **场地观测** `VenueObservation`：实际场地、在场人数；
3. **抽样确认**：每场上限为样本抽取（最少 3 人且不低于班级 10%），
   学生以**学期假名 token** 出现，未被抽中的学生不产生任何事件。

任一方缺失或矛盾（场地不符、人数异常、样本不足、替代无依据、补课未挂原场次），
该场不成立"已完成"，进入待确认/复核，而不是直接判违规——原因在 `reasons` 中逐条给出。

### 4.1 隐私最小化

- 系统内不存在课堂影像、体测分数字段；
- 学生身份映射 `IdentityVault` 与业务账本**物理分离**，账本里只有 token；
- token 由 BLAKE2b（学期随机盐 + 学号）生成：同学期稳定、跨学期不可链接。

### 4.2 运动时长防虚增

- 有效时长 = min(教师申报时长, 该活动类型标准时长上限)；申报 120 分钟的体育课封顶 40，
  封顶动作在 `flags` 留痕；
- 同一 (token, 场次) 的重复签到只计最早一次，重复事件保留并标 `duplicate_signin:*`，
  **绝不增加人数或时长**；
- 离线补签受理时限 48 小时（`OFFLINE_ACCEPT_HOURS`），超时仅留痕（`offline_late:*`）不计入，
  防止事后集中补签把没上的课"签出来"；
- 伤病适配按学生、按技能折减（`InjuryAdaptation.adjusted_minutes`，0 为见习），
  必须引用医嘱/申请依据，且只影响该生，不影响班级场次成立。

### 4.3 授课形态

`SessionMode`：normal / rain_alt / heat_alt / rescheduled / free / exam_drill / makeup。

- 降雨、高温替代与调课必须给依据编号；
- **整节自由活动**与**只练考试项目**：身体活动时长照算（不能说谎称没动），
  但标记 `whole_free_play` / `exam_drill_only`，且不产生计划技能覆盖（见第 6 节）；
- 补课必须挂接被缺场次 `makeup_for`。

## 5. 事件账本与实况还原（ledger.py）

账本 `EventLedger` **只追加**：教师记录、场地观测、抽样签到、调课（`ScheduleChange`）、
天气触发、临时占课（`takeover`，记录占用科目）、补课安排、复核结论，均带全局序号。

`rebuild_class(class_id, slots, ..., current_week)` 重放至当前教学周，逐场三方确认，
把每个计划场次归入状态：

| 状态 | 含义 |
|---|---|
| `completed` / `completed_makeup` | 正常完成 / 补课场次完成 |
| `taken_over` | 被临时占课，挂待补课 |
| `weather_pending` | 触发了降雨高温但未执行替代，挂待补课 |
| `rescheduled` | 有审批调课，不算缺口 |
| `missing` | 课表有、无任何事件（疑似阴阳课表） |
| `in_review` | 三方确认未过 |

即使"场地冲突 → 临时占课 → 离线补签"连续发生，重放仍能还原：
真正完成的内容（`sessions` 中含实际技能/形态/时长）、缺口（`pending_makeup`）、
补课安排（`makeup_schedule` 原场次→补课场次，完成后原场次回填为 completed 并记入 `made_up`）。
未来周次不参与核对，避免把"还没上"误报为缺口。

## 6. "教会、勤练、常赛"覆盖规则（coverage.py）

评价单位是**技能目标 × 班级**，不是学生体测分数。每个 `SkillGoal` 声明
teach/practice/match 计划周次；覆盖只统计**经三方确认且实际传授该技能**的场次，
自由活动与纯应考训练被排除在技能覆盖之外（但仍计运动时长）。

- **教会**：计划教授周内（含回填该周的补课）至少 1 节确认授课；
- **勤练**：计划练习周中实际命中的周数占比（按周去重，同一周多节课不重复计分）；
- **常赛**：计划赛事周中确认的班级赛事占比；
- **补课回填**：MAKEUP 场次按其挂接原场次所在周归类，补上即兑现原周目标；
- 每个比例附带 `evidence`（命中场次 key）与 `gaps`（人话缺口，如"勤练缺口：2/4 周"），
  对学校、教研、公众都可解释。

## 7. 异常识别与教研复核（review.py）

`detect_anomalies` 基于重放结果做规则识别（阈值是**教研介入线，不是处罚线**）：

| 异常 | 触发 |
|---|---|
| `yin_yang_schedule` | 课表场次完全无教师/场地/学生事件，且未被调课或补课覆盖 |
| `exam_drill_pattern` / `free_play_pattern` | 连续 2 场只练考试项目 / 整节自由活动 |
| `takeover_chain` | 连续 2 起临时占课 |
| `venue_conflict` / `capacity_breach` | 实际场地冲突 / 实际人数超安全容量 |
| `signin_anomaly` | 重复签到、超时补签集中出现 |

异常班级由 `ReviewBoard` 开案进入"教研复核"状态。复核结论四选一：
无异常（天气/调课有据，`cleared`）、确认缺口并安排补课（`makeup_ordered`）、
材料不足退回补证（`need_more`）。已结案不可二次裁定。**复核期间不产生任何对外结论**。

## 8. 分级可见性（visibility.py）

| 视图 | 可见内容 | 硬边界 |
|---|---|---|
| 公众 | 学校级聚合：场次完成率、教会/勤练/常赛比例、待补赛场次数 | 计入班级 < 3 整体抑制；小计数单元格抑制；复核未结案班级整班排除（不审不判）；无班级排名 |
| 家长 | 仅本人子女：伤病适配记录、该生经确认场次的有效时长 | 凭据校验亲子关系，越权即 `AccessDenied`；不含他人数据、不含签到明细、不回传真实学号 |
| 教研员 | 班级级证据、场次 key、事件序号、复核裁定 | 学生身份仍为 token；实名调取走单独授权（系统外流程） |

## 9. 关键场景串联（均有测试）

1. **降雨**：`weather_trigger(rain)` → 教师按 rain_alt 在体育馆授课并引用 `POL-RAIN-01`
   → 场地观测一致 → 正常计完成；只触发未执行替代则 `weather_pending` 挂补课。
2. **高温**：同 rain，走 heat_alt。
3. **场地冲突 → 占课 → 离线补签**：冲突留证、占课记 `taken_over`，
   49 小时后的离线补签超时不计 → 场次挂待补课；第 2 周 MAKEUP 挂接原场次 → 原场次回填完成。
4. **阴阳课表**：课表 5 天、实际 3 天有事件 → 缺失场次进入复核，与批准版本逐条对照。
5. **只练考试项目**：时长照算、连续 2 场触发复核、对应技能"教会/勤练"不计覆盖。
6. **伤病学生**：凭医嘱适配 10 分钟/见习，仅该生时长折减，家长可在本人视图看到依据。

## 10. 代码地图与运行

```
pe_domain/
  models.py     场地/教师/技能目标/方案槽位/天气替代/伤病适配（不可变对象）
  plans.py      方案校验（7 类规则）+ 版本库（提交/批准/取代/历史）
  events.py     三方确认、去重、离线时限、时长封顶、伤病折减、假名
  coverage.py   教会/勤练/常赛可解释覆盖
  review.py     异常识别 + 复核台账（开案/补证/澄清/补课令）
  ledger.py     只追加账本 + 单班实况重放
  visibility.py 身份保管处 + 公众聚合 + 家长视图
test_pe_domain.py  31 个领域规则测试
service_contract.py 3 个服务契约测试（原有健康检查）
```

```bash
python3 service.py --check   # 基础检查
npm test                     # 契约 + 领域全部 34 个测试
```

## 11. 尚未实现（后续迭代边界）

- 持久化：当前账本/版本库为内存实现，落地时事件按 (school, seq) 只追加存储，
  IdentityVault 独立库且密钥分权；
- 时间维度：`effective_on` 以序号占位，生产中改用事件时间戳与方案生效区间；
- 抽样策略：现为固定最小样本，生产应由独立抽样服务按场次决定名单且对教师不可见；
- 教研授权实名调取、家长凭据签发（OAuth/政务认证）为系统外流程，本设计只表达边界与拒绝语义。
